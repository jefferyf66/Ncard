## 一、必须修复项（P1，共 8 项）

### P1-1 访客授权弹窗完全没有样式（渲染级 bug）
- 位置：`pages/preview/index.wxml:312-335`
- 问题：`auth-modal / avatar-btn / avatar-preview / avatar-placeholder / avatar-btn-text / nickname-input / nickname-ph` 共 7 个类在 `preview/index.wxss` 中**一个都没定义**。弹窗既无全屏遮罩、无居中、无白色卡片容器，头像选择按钮和昵称输入框会以裸元素堆在页面底部。
- 建议：补齐样式——遮罩复用 `.delete-modal` 的 fixed + rgba(15,23,42,0.5) + 居中方案；内容卡复用 `.modal-content`（600rpx、radius 24rpx、padding 48rpx 40rpx）；头像按钮 160rpx 方角 + 蓝边框；昵称输入框复用 edit 页 `.form-input` 规格（#F8FAFC 底、4rpx 圆角、80rpx 高）。

### P1-2 「邀请已失效」警告显示为蓝色信息条（语义错误）
- 位置：`pages/team/join.wxml:8`（`class="cardform-tip warn"`）；`join.wxss` 中无任何 `.warn` 规则
- 问题：失效/已使用是警示语义，实际渲染成与「负责人已预填」一样的蓝色提示条，用户会误读。
- 建议：补 `.cardform-tip.warn { background:#FEF2F2; border-color:#FECACA; color:#DC2626; }`，与 account 页 danger 色系对齐。

### P1-3 导航栏颜色脱离品牌色板
- 位置：`pages/preview/index.json` 与 `pages/team/detail.json` 用 `#165DFF`（Arco 蓝，全库仅此两处）；`pages/edit/index.json` 用白底黑字，与全局蓝底白字导航相反
- 问题：全 App 导航栏出现三种状态：#3B82F6（全局/account/admin）、#165DFF（preview/team detail）、#FFFFFF（edit）。用户在页面间切换时导航栏颜色跳变。
- 建议：preview、team/detail 改回 `#3B82F6`；edit 若想突出表单沉浸感应走 `navigationStyle:custom` 自绘头部，否则统一 `#3B82F6`。二选一拍板。

### P1-4 首页顶部内边距计算失效（无效 CSS 变量）
- 位置：`pages/index/index.wxss:24` — `padding-top: calc(var(--status-bar-height) + 20rpx)`
- 问题：`--status-bar-height` 是 uni-app 的变量，微信小程序原生不存在 → 该声明整体失效，padding-top 回落为 0，「我的名片」标题贴死导航栏下沿，设计意图的 20rpx 呼吸空间丢失。
- 建议：改为 `padding-top: 20rpx;`（页面使用默认导航栏，无需状态栏补偿；若未来改 custom 导航再用 `env(safe-area-inset-top)`）。

### P1-5 一批可点元素低于最小触控目标（44px / 88rpx）
- 位置与元素（均为纯文本热区，无 padding 撑高）：
  - `pages/index/index.wxml:12` 添加到桌面 `.desktop-link`（24rpx 字）
  - `pages/index/index.wxml:117-119` 底部协议链接 ×2（24rpx）
  - `pages/edit/index.wxml:217,315` 「+ 添加」`.add-btn`；`:248` 经历「删除」；`:324` 附件「删除」
  - `pages/team/detail.wxml:142-143` 成员「编辑/移除」；`:65` 「用邀请码加入 ›」
  - `pages/preview/index.wxml:180` 「查看全部 ›」；`:35` 「查看团队 ›」
  - `pages/visitors/index.wxml:48` 错误态「点击重试」（绑在 26rpx 文本上）
- 问题：实际热区普遍只有 30~50rpx 高（15~25px），约为微信规范的 44px 一半，误触率高；「删除」「移除」这类破坏性操作尤其危险。
- 建议：统一加 `min-height:88rpx` + 负 margin 补偿（或 `padding:20rpx` 且外层负 margin 抵消），破坏性操作（删除/移除）建议再加 8rpx 间距防连点。

### P1-6 list 页 emoji 图标与全 App 纯 CSS 图标体系冲突
- 位置：`pages/list/index.wxml:33,37,51`（📞 ✉️ 👔）、`:44`（› 文字箭头，尚可）
- 问题：index/preview/edit/profile 全部是手工 CSS 线性图标（2-3rpx 描边、统一 #3B82F6），list 页突然出现彩色 emoji——跨机型渲染不可控（安卓/ iOS 表情差异）、视觉重量和描边风格完全不符，且 👔 与「名片夹」语义牵强。
- 建议：📞✉️ 换 CSS 图标（preview 页已有现成 `.icon-phone/.icon-mail` 可复制）；空态 👔 换成 index 空态同款 `.icon-card` + 圆底方案。

### P1-7 主保存按钮无禁用/提交中状态
- 位置：`pages/edit/index.wxml:347-351`（`.save-btn`），对照 `team/create.wxml:50` 有 `{{isSubmitting ? 'disabled' : ''}}`
- 问题：名片保存是全 App 最高频写操作，保存期间按钮外观无任何变化（team 系列页都有「创建中.../加入中...」+ opacity），用户会重复点击。
- 建议：补 `disabled` 类（opacity 0.6 + pointer-events 提示文案「保存中...」），与 team 页模式对齐。

### P1-8 预览页公众号二维码弹窗使用内联样式
- 位置：`pages/preview/index.wxml:151-155`（style="padding:40rpx" / "width:420rpx..." / 内联按钮 #3B82F6、radius 4rpx、font-size 30rpx）
- 问题：唯一一处内联样式弹窗，按钮样式（纯色 #3B82F6）与全 App 主按钮（渐变）不一致，后续改主题必然漏改。
- 建议：抽成类（可复用 `.modal-content` + `.modal-btn.confirm` 渐变规格）。

## 二、可选优化项（P2，按收益排序）

### 设计一致性类

**P2-1 圆角体系 10 档并存（收益最大的单项收敛）**
- 实测取值：4 / 8 / 12 / 14 / 16 / 18 / 20 / 24 / 28 / 40 / 48rpx。示例：输入框 4rpx（edit）vs 12rpx（team/create）vs 8rpx（list segment）；主按钮 4rpx（save-btn）vs 12rpx（join-btn）vs 16rpx（team primary-btn）vs 40rpx 药丸（empty-btn）vs 48rpx（crop）。
- 建议：收敛为 3 档并写进 app.wxss CSS 变量——`--radius-sm:8rpx`（输入框/小件）、`--radius-md:16rpx`（按钮/弹层内件）、`--radius-lg:24rpx`（卡片/弹窗）。crop 页属全屏工具页，可豁免。

**P2-2 主按钮三种做法并存**
- save-btn 纯色 #3B82F6（edit）/ 渐变 135° #3B82F6→#2563EB（team 全家、join-btn、retry-btn 160°、auth-btn-agree 160°）/ 蓝紫渐变 #3B82F6→#8B5CF6（index empty-btn:453、add-icon-wrapper——紫色脱离品牌双色）。配套字号 34/30/28rpx 不等。
- 建议：主按钮统一「渐变 135° #3B82F6→#2563EB + 30rpx/600」一种规格（app.wxss 定义 `.btn-primary`），empty-btn 去紫；save-btn 收编。

**P2-3 灰阶调色板三套并存**
- slate 系（#0F172A/#334155/#475569/#94A3B8/#E2E8F0，核心页）、飞书系（#1F2329/#646A73/#8F959E/#F5F7FA/#E5E6EB，list 页）、Tailwind gray（#111827/#374151/#9CA3AF，account/admin）。
- 建议：统一 slate 系，list/account/admin 换色即可（纯查找替换，无布局风险）。

**P2-4 页面背景三族**
- 暖调渐变（edit/preview #FAFBFC→#FEFCF9→#F6F8FC）、蓝→暖渐变（profile/visitors/team #EFF6FF→#F8FAFC→#FEFCF7）、纯灰 #F5F7FA（list/account/admin）、橙→蓝（index，Hybrid 基座属设计意图可保留）。
- 建议：非 tab 内容页统一一族；list 页作为 tab 页建议与 index 同用暖调或统一 #F6F8FC 系。

**P2-5 头像形状不统一**
- index 名片卡 140rpx/16rpx 圆角方、edit/preview/profile/visitors 4rpx 锐角方、list 页 112rpx **正圆**、团队页正圆。
- 建议：个人名片场景统一 4rpx 锐角方（Hybrid 基调），list 页跟随；团队组织头像可保留圆形以示区分（这样反而形成语义）。

**P2-6 同名异形图标**
- `.icon-card`：index 空态横版 56×40（:562）/ profile 竖版 36×44（:89）/ team detail 横版 36×28（:172）；`.icon-team`：tab bar 双圆 vs team list 空态卡+人头。各自独立文件不冲突，但语义同一、形态三种。
- 建议：统一「名片=横版、团队=双人」一种画法，按需缩放。

**P2-7 错误态图标两种**
- index 错误态：红底圆 + 红色「!」文本（index.wxss:469）；preview 错误态：灰色 `icon-alert`（:757）。语义同为「加载失败」，一个红一个灰。
- 建议：统一 preview 的 CSS 线性画法、色值改 #EF4444，或统一灰（错误标题已是红字）。

**P2-8 弹窗两种模式 + 三套实现**
- preview 删除确认/授权：居中 dialog（radius 24rpx、按钮 4rpx）；team detail 邀请/配置：底部 sheet（radius 28rpx 顶角、按钮 16rpx）；account/admin：又一套居中 dialog（radius 20rpx、按钮 12rpx）。z-index 1000/200/100 也不统一。
- 建议：确认类（删除/注销）居中 dialog；创建/表单类底部 sheet——按此归位，z-index 统一 1000。

### 排版与可读性类

**P2-9 页面大标题层级不一**
- team 系页 44rpx/700 + 副标题；index/list 40rpx；account/admin 32rpx 且页内自绘「‹ 返回 账号设置」标题行 + 默认导航栏「账号设置」形成**双标题栏**。
- 建议：tab 外内容页统一 40rpx/700；account/admin 删掉自绘 nav 行（默认导航栏已有标题+返回），约可省 2 行 wxml + 视觉噪音。

**P2-10 小字号 + 低对比灰的组合偏多**
- 22rpx（≈11px）出现在 form-hint、attach-meta、badge-text、tc-note、action-sub 等，配 #94A3B8（对白底对比度约 3.1:1，WCAG AA 正文要求 4.5:1）。
- 建议：22rpx 上调 24rpx；#94A3B8 仅用于装饰性文本，说明性文本改 #64748B。visitor-level-badge 20rpx 同理。

**P2-11 加载 spinner 尺寸/速度不一**
- 64rpx/1s（index/edit/preview/visitors）vs 56rpx/0.8s（team list/detail）。
- 建议：统一 64rpx/1s，并上移 app.wxss（目前 6 个文件各抄一份 `@keyframes spin`）。

**P2-13 单位混用**：edit 页 `.form-input/.form-textarea/.form-input-wrap` 用 `border:1px`，同文件 `.exp-input` 用 `2rpx`——1px 在高分屏不缩放，与 2rpx 视觉不等宽。统一 rpx。
