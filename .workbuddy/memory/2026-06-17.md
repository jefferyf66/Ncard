## 分享卡片图片跨设备无法访问修复（共 3 轮迭代）

### 第一轮：云函数上传 + 云函数 getTempFileURL（失败）
- 云函数 uploadShareImage 以管理员身份上传 + getTempFileURL
- 结果：URL 在其他设备浏览器打不开，签名绑定云函数运行时上下文

### 第二轮：客户端 uploadFile + 客户端 getTempFileURL（失败）
- 客户端 wx.cloud.uploadFile 直传 + 客户端 wx.cloud.getTempFileURL
- 结果：接收方仍看不到图片，「仅创建者可读写」私密文件的临时链接 10 分钟有效但可能仅限小程序上下文

### 第三轮：客户端 uploadFile + cloud:// fileID（失败）
- 微信文档「基础库 2.8.1 起分享图支持云图片」，但 cloud:// 可能仍需要云环境认证
- 结果：接收方看不到

### 第四轮：本地临时路径 + promise 属性模式（失败）
- 掘金文章称 canvasToTempFilePath 本地路径可直接用于分享
- 结果：接收方看不到，豆包确认「微信不接受本地路径、临时缓存路径」

### 第五轮：HTTP 云函数 serveShareImage（当前方案）✅
- **根因确认**：豆包分析指出 getTempFileURL 生成的 `?sign=xxx` 被微信分享拉图当作 token 鉴权拦截
- 解决方案：HTTP 云函数 `serveShareImage` 提供 clean URL（无 sign 参数）
- 新增文件：
  - `cloudfunctions/serveShareImage/index.js` — HTTP 云函数，读云存储返回 image/png
  - `cloudfunctions/serveShareImage/package.json`
- 修改文件：
  - `cloudfunctions/uploadShareImage/index.js` — 上传后返回 clean URL（从 fileID 提取 env-id 构造）
  - `index.js` — 新增 `_uploadAndGetCleanUrl()` 方法；`_generateShareCardSync` 调用云函数获取 clean URL
  - `index.js` — `onShareAppMessage` 使用 `promise` 属性模式
- 待用户操作：CloudBase 控制台 → HTTP 访问服务 → 启用 → 部署 serveShareImage
