### Bug #2: 气泡卡片内部名片右侧阴影截断
**根本分析**：`cardShadowBlur=32rpx` 在 600px 画布上约 27px，向右溢出 ~14px。Canvas 宽度 = 卡片宽度 → 右侧阴影被画布边界硬截断，视觉上看起来像右侧"被切掉一块"。
**上次回滚的教训**：shadowBleed 参与气泡适配 → totalW 增大 → 缩放比变小 → 卡片内容区缩窄 → 文字溢出恶化。
**本次修复（v5 方案）**：阴影留白在气泡适配**之后追加**，不参与缩放。
- `_computeCanvasSize`：气泡适配仅对 (cardW, cardH+bannerH) → 适配后计算 shadowBleed = ceil(shadowBlurPx/2)+1 → 返回 `{width, height, bannerHeight, cardHeight, shadowBleed}`
- `_ensureLayout`：`layout.canvasW = dims.width + shadowBleed*2`（完整画布宽），`layout.shadowBleed = shadowBleed`
- `generate()`：canvas.width = canvasW * dpr，ctx.translate(shadowBleed, 0) 预留左侧阴影空间
- `_drawBanner`：fillRect(-shadowBleed, 0, canvasW, bh) 横幅填满画布全宽
- `_exportAndResolve`：导出尺寸用 canvasW
- `getCurrentDimensions`：返回含阴影留白的完整尺寸
- **关键**：`layout.w`（卡片内容区宽度）不变，所有文字布局和截断计算均不受影响

## 12:27 诊断并修复云函数跨用户头像权限问题

用户反馈云函数已部署但跨用户头像仍无法显示。

### 根因
云存储设为「仅创建者可读写」时，云函数中的 `cloud.getTempFileURL()` **仍遵守文件 ACL**，对非创建者的文件返回 `STORAGE_EXCEED_AUTHORITY`（status != 0, tempFileURL 为空）。

云函数虽有数据库管理员权限，但存储层 `getTempFileURL` 以"获取临时下载链接"方式工作 → 文件 ACL 检查不通过 → 返回空 URL → 客户端收到空字符串 → 不替换 `cloud://` URL → 渲染层加载失败。

### 核心修复
**方案**：在 `getTempFileURL` 失败时，降级使用 `cloud.downloadFile()`（云函数环境中拥有管理员权限，可绕过文件 ACL），将文件 Buffer 转为 base64 data URL 返回。

**降级链路**（云函数内部）：
```
getTempFileURL (批量)
  ├─ status=0 → HTTPS 临时 URL ✅
  └─ status≠0 → downloadFile → Buffer → base64 data URL ✅
       └─ 失败 → 空 URL → 客户端兜底默认头像
```

### 修改文件

| 文件 | 改动 |
|------|------|
| `cloudfunctions/resolveCloudUrls/index.js` | 重写：新增 Step 2 downloadFile 降级（-63/+122行） |
| `cloudfunctions/resolveCloudUrls/config.json` | 添加 `permissions.openapi` 配置 |

### 关键实现细节

1. **Step 1 — 批量 `getTempFileURL`**：对同用户文件直接返回 HTTPS URL
2. **Step 2 — 逐个 `downloadFile`**：对 ACL 拒绝的文件（status ≠ 0），`await cloud.downloadFile({ fileID })` → `Buffer.toString('base64')` → `data:image/jpeg;base64,...`
3. **MIME 推断**：从 fileID 扩展名推断（jpg/jpeg/png/gif/webp/bmp/svg）
4. **缓存**：data URL 同样缓存 115 分钟，避免重复下载
5. **完全失败**：缓存空 URL 5 分钟避免重复尝试

### 客户端兼容性

| 场景 | `data:image/...` 兼容性 |
|------|------------------------|
| WXML `<image src="...">` | ✅ 完美支持 |
| Canvas `createImage().src` | ⚠️ 部分旧版微信可能不支持 → `onerror` → 回退占位头像 |
| `wx.previewImage` | ✅ 支持 |

### 部署注意事项
- 需重新部署 `resolveCloudUrls` 云函数
- 建议云函数超时设为 **10 秒**（处理多个大图片时需要）
- 典型场景（3-5 个头像，每个 50KB）→ 响应 < 2 秒
- 单个 data URL 通常 60-150KB，5 个约 500KB，远低于云函数 6MB 响应限制

## 16:22 分享卡片 Canvas 节点就绪死循环修复

用户真机测试反馈效果没有改善，console 报"canvas节点未就绪，延迟重试"。

### Bug #1（主因）：`_isCanvasReady()` 永远返回 false
`wx.createSelectorQuery().exec()` 是**异步**的，但 `return ready` 是**同步**的 → `ready` 永远是初始值 `false`。
→ `_preGenerateShareCardWithKey` 中 `_isCanvasReady() === false` → 每次 `setTimeout(100ms)` 重试 → 无限循环
→ `shareCard.generate()` 从未被真正调用 → v3 新版视觉从未渲染 → "效果没有改善"

### Bug #2：shareCard.generate() 缺少页面作用域
`wx.createSelectorQuery()` 无 `.in(this)`，真机 type="2d" Canvas 可能找不到节点。

### 修复（2文件）
| 文件 | 改动 |
|------|------|
| `pages/index/index.js` | 删除 `_isCanvasReady()` 方法（死代码）；`_preGenerateShareCardWithKey` 改为直接在 catch 中退避重试（3 次，100/300/600ms）；传入 `pageContext: this` |
| `utils/shareCard.js` | `generate()` 新增 `options.pageContext` → `.in(pageContext)` 作用域查询 |

### 原理
- 不再提前"检查" canvas 是否就绪（那个检查本来就是假的）
- 直接调用 `shareCard.generate()`，让它内部的 `exec()` 异步查询
- 如果 canvas 真的还没挂载到 DOM，`exec` 的 result 会是 null → reject → catch 中退避重试
- 正常情况：页面渲染完成后 canvas 就绪 → `exec` 返回有效节点 → 正常绘制

### 关键逻辑
```javascript

    // 退避延迟后重试
}
// 其他错误直接放弃
```

## 17:11 分享图片空白修复 — Object.freeze 静默吞属性 (v4 引入的回归)

用户真机截图：分享卡片完全空白，只显示微信原生小卡片（姓名+公司），无 Canvas 生成的自定义图片。

### 根因
`computeLayout()` 返回 `Object.freeze(layout)`，但 `_ensureLayout()` 后续给 frozen 对象追加 3 个新属性：
```javascript
_activeLayout = computeLayout(dims.width, cardH)  // frozen!
_activeLayout.bannerHeight = bannerH      // ❌ 静默失败 → undefined
_activeLayout.cardOffsetY = bannerH       // ❌ 静默失败 → undefined
_activeLayout.totalH = dims.height        // ❌ 静默失败 → undefined
```
**致命链**：`totalH=undefined → canvas.height=NaN → 绘制无效 → 导出空白图 → onShareAppMessage 拿不到 imageUrl → 微信降级显示原生格式**

### 修复
`shareCard.js:145`: `Object.freeze(layout)` → `return layout`，添加注释说明不 freeze 的原因。

### 教训
JS 非严格模式下对 frozen 对象赋值**不抛错**，只静默忽略。在需要后续扩展属性的对象上不能用 freeze。
