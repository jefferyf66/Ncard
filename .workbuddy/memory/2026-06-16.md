用户反馈：从首页点击名片数进入名片夹列表页，console 报 `FUNCTION_NOT_FOUND` 错误 + `Failed to load image cloud://...`。

### 修复（3文件，-3/+38行）

| 文件 | 改动 |

### 降级链路
`resolveCloudUrls 云函数` → (失败) → `getTempFileURL` (客户端API) → (失败) → **默认头像**

## 12:27 诊断并修复云函数跨用户头像权限问题

用户反馈云函数已部署但跨用户头像仍无法显示。

### 根因
云存储设为「仅创建者可读写」时，云函数中的 `cloud.getTempFileURL()` **仍遵守文件 ACL**，对非创建者的文件返回 `STORAGE_EXCEED_AUTHORITY`（status != 0, tempFileURL 为空）。

云函数虽有数据库管理员权限，但存储层 `getTempFileURL` 以"获取临时下载链接"方式工作 → 文件 ACL 检查不通过 → 返回空 URL → 客户端收到空字符串 → 不替换 `cloud://` URL → 渲染层加载失败。

### 核心修复
**方案**：在 `getTempFileURL` 失败时，降级使用 `cloud.downloadFile()`（云函数环境中拥有管理员权限，可绕过文件 ACL），将文件 Buffer 转为 base64 data URL 返回。

**降级链路**（云函数内部）：
```
getTempFileURL (批量)
  ├─ status=0 → HTTPS 临时 URL ✅
  └─ status≠0 → downloadFile → Buffer → base64 data URL ✅
       └─ 失败 → 空 URL → 客户端兜底默认头像
```

### 修改文件

| 文件 | 改动 |
|------|------|
| `cloudfunctions/resolveCloudUrls/index.js` | 重写：新增 Step 2 downloadFile 降级（-63/+122行） |
| `cloudfunctions/resolveCloudUrls/config.json` | 添加 `permissions.openapi` 配置 |

### 关键实现细节

1. **Step 1 — 批量 `getTempFileURL`**：对同用户文件直接返回 HTTPS URL
2. **Step 2 — 逐个 `downloadFile`**：对 ACL 拒绝的文件（status ≠ 0），`await cloud.downloadFile({ fileID })` → `Buffer.toString('base64')` → `data:image/jpeg;base64,...`
3. **MIME 推断**：从 fileID 扩展名推断（jpg/jpeg/png/gif/webp/bmp/svg）
4. **缓存**：data URL 同样缓存 115 分钟，避免重复下载
5. **完全失败**：缓存空 URL 5 分钟避免重复尝试

### 客户端兼容性

| 场景 | `data:image/...` 兼容性 |
|------|------------------------|
| WXML `<image src="...">` | ✅ 完美支持 |
| Canvas `createImage().src` | ⚠️ 部分旧版微信可能不支持 → `onerror` → 回退占位头像 |
| `wx.previewImage` | ✅ 支持 |

### 部署注意事项
- 需重新部署 `resolveCloudUrls` 云函数
- 建议云函数超时设为 **10 秒**（处理多个大图片时需要）
- 典型场景（3-5 个头像，每个 50KB）→ 响应 < 2 秒
- 单个 data URL 通常 60-150KB，5 个约 500KB，远低于云函数 6MB 响应限制
