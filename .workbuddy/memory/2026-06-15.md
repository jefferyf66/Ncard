## 18:30 分享卡片动态适配系统（v2）

### 背景
用户担心微信调整卡片消息格式后，每次都要手动改代码。在讨论 API 稳定性后，决定实施比例化布局引擎 + 云端配置方案，实现"换尺寸只改一处"。

### 实施

**`miniprogram/utils/shareCard.js` — 完全重构（~490行 → ~650行）：**

#### 核心变更：比例化布局引擎

所有硬编码像素（`L_AVATAR=110`, `L_BANNER_H=100`, `dividerY=230` 等 24 个值）全部替换为 `computeLayout(w, h)` 的比例计算：

```
padding      = w × 0.05          (5% 宽度)
bannerH      = h × 0.25          (25% 高度)
avatarSize   = (h×0.75) × 0.367  (内容区 36.7%)
nameFontSize = w × 0.06          (6% 宽度)
...等 24 项全部比例化
```

**验证**：800×400 下新旧值完全一致（24/24 零差异），无任何视觉回归。

#### 新增：云端配置热更新

- `_fetchRemoteDimensions()` — 从云数据库 `config` 集合读取 `{ _key: "shareCardDimensions", width, height }`
- 读取失败 → 回退到 DEFAULT_DIMENSIONS (800×400)
- `_ensureLayout()` — 首次调用时异步获取配置，之后内存缓存复用（防并发）
- 新增 `refreshLayout()` 公开 API — 强制刷新布局（管理后台更新配置后调用）
- 新增 `getCurrentDimensions()` 公开 API — 供页面层获取当前生效尺寸

#### 缓存版本化

```
旧 key: cardKey (如 "abc123")
新 key: cardKey_800x400 (如 "abc123_800x400")
```

效果：云端更新配置改为 `750×500` → key 变为 `abc123_750x500` → 旧 `_800x400` 缓存自然失效，零代码部署。

#### 绘制函数改造

所有绘制函数增加 `layout` 参数：
- `_drawLayout(ctx, card, avatarSrc, iconReady, layout)` — 主布局
- `_drawAppIcon(ctx, x, y, layout)` — 图标尺寸用 `layout.appIconSize`
- `_drawContactInfo(ctx, card, layout)` — 右对齐用 `layout.rightEdge`
- `_exportAndResolve(canvas, versionedKey, now, layout, resolve, reject)` — 导出用 `layout.w/h`

`_drawAvatar` 签名不变（已经接受 x/y/size/radius 参数）。

#### 导出 API

```
module.exports = {
  generate: generate,                    // 签名不变
  getCurrentDimensions: getCurrentDimensions,  // 新增
  refreshLayout: refreshLayout                  // 新增
}
```

### 云端配置操作指南

**首次设置：**
1. 云开发控制台 → 数据库 → 新建集合 `config`
2. 添加记录：
```json
{
  "_key": "shareCardDimensions",
  "width": 800,
  "height": 400
}
```
3. 权限：所有用户可读

**热更新尺寸（无需发布小程序）：**
只需修改 `config` 集合中对应文档的 width/height 值，用户下次打开分享时自动使用新尺寸。

### 调用方影响

- `pages/index/index.js` → `shareCard.generate('#shareCanvas', card, { cardKey })` **零改动**
- `test/shareCard.test.js` → 引用方式不变
- `test/shareFlow.test.js` → 引用方式不变
- Canvas WXML 元素 → 隐藏元素无需改动尺寸（JS 中动态设置）

## 18:54 隐私政策审核不通过 — 修复

### 审核拒绝原因
「默认自动同意《用户服务协议》及《隐私政策》，应当由用户主动阅读后自行选择」

### 根因（4 项）
| # | 问题 | 影响 |
|---|------|------|
| P0 | `app.json` 缺少 `"__usePrivacyCheck__": true` | 隐私系统未激活，弹窗永不显示 |
| P0 | WXML/WXSS 类名全部不匹配 | 弹窗零样式，显示为无格式文本 |
| P0 | `app.js:initPrivacy()` 用 `wx.showModal` + resolve 格式错误 | 审核工具看到极简系统弹窗 |
| P1 | 自定义弹窗「同意」未调用 resolve | 隐私状态不同步 |

### 修正（4 文件，~85 行）

**`app.json` — +1 行：**
- 新增 `"__usePrivacyCheck__": true`（第 23 行）

**`app.js` — initPrivacy() 重写：**
- 旧逻辑：`wx.showModal` 系统弹窗 → `resolve({ event: 'agree', button: 'agree' })`
- 新逻辑：存储 `resolve` 到 `app._privacyResolve`，不弹系统弹窗
- 新增 `_privacyResolve: null` 实例属性

**`pages/index/index.js` — 3 处修改：**
1. `handlePrivacyAgree(e)` — 添加 try/catch 调用 `app._privacyResolve({ event: 'agree' })` 兜底
2. `handlePrivacyDecline()` — 添加 try/catch 调用 `app._privacyResolve({ event: 'disagree' })` +「重新查看/退出小程序」双选对话框
3. `onShow()` — 前置检测 `app._privacyResolve`，若 pending 且弹窗未显示则自动触发

**`pages/index/index.wxss` — 完全重写隐私样式段（~65 行）：**

  - `privacy-btn-agree` — 蓝色渐变按钮 #3B82F6→#2563EB

## 19:26 访客追踪系统两期优化

### 背景
用户确认隐私协议后，已具备获取用户身份的基础，应将匿名访客追踪逻辑升级为更合理的三级身份体系。两期优化合并实施。

### 第一期：隐私授权联动优化（3 项）

**1. 隐私同意后静默注册 visitor_profiles（index.js +25 行）**

`handlePrivacyAgree()` 新增 `_registerVisitorProfile()` 调用：
- 隐私同意后自动获取 openid → `visitor_profiles.count({openid})` → 不存在则 `add({openid, nickname:'', avatarUrl:'', ...})`
- 仅建立 openid 占位记录，后续通过创建名片(L3)或 auth-banner(L2)补充真实身份
- 静默执行，不影响主流程（所有错误被 catch）

**2. auth-banner 去延迟 + 冷却期优化（preview.js ~15 行）**

- 移除 3 秒 `setTimeout` → 改为立即 `setData({showAuthBanner:true})`
- 冷却期从「7 天时间戳」改为「同一自然日」：比较 `YYYY-M-D` 日期字符串而非毫秒差
- `dismissAuthBanner()` 和 `onAuthUserInfo()` reject 路径同步更新
- 存储 key 从 `auth_banner_dismissed_at` → `auth_banner_dismissed_date`

**3. 删除 profile 页 wx.getUserInfo 死代码（profile.js -15 行 / profile.wxml -3 行）**

- 删除 `getUserInfo()` 方法（wx.getUserInfo 仅返回"微信用户"，无实际作用）
- WXML 移除登录按钮 `bindtap="getUserInfo"`，默认名称从"点击登录"→"微信用户"

### 第二期：身份体系联动（2 项）

**4. 创建名片后同步 visitor_profiles → L3 升级（edit.js +35 行）**

`saveCard()` 成功后（仅新建，非编辑）→ 调用 `_syncVisitorProfile()`：
- 获取 openid → visitor_profiles upsert（count→add/update）
- 写入姓名(`name`)、头像(`avatar`)到 `nickname`/`avatarUrl` 字段
- 之后他人查看此用户名片时，initVisits 云函数自动识别为 L3 卡片用户

**5. 合并首页 visit 云函数调用（initVisits +25 行 / index.js ~30 行重构）**

云函数新增 `getMyVisitorDashboard` action：
- 三路 `Promise.all` 并行：总数 + 回访数 + 最近 20 条访客
- 替代先前两次独立调用（getMyVisitorStats + 客户端 _loadRecentVisitors）

index.js 重构：
- `_loadVisitorStats()` → 使用 `getMyVisitorDashboard` 单次调用
- 新增 `_processRecentVisitors(rawVisits)` 聚合函数，云函数/降级路径共用
- `_loadRecentVisitors()` 标记 deprecated，保留向后兼容
- `_loadVisitorStatsDirect()` 降级路径也通过 `_processRecentVisitors` 统一
